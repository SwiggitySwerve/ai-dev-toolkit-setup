# Claude Code Configuration and Authentication

This guide covers how to authenticate, configure settings, set up project-specific context, and manage your Claude Code environment.

---

## Authentication

Claude Code supports two authentication methods: interactive OAuth (for Anthropic subscribers) and API key (for direct API users).

### Method 1: Interactive OAuth (Anthropic Subscription)

When you run `claude` for the first time, it launches an OAuth flow:

```bash
claude
```

1. Claude Code prints a URL and attempts to open it in your default browser.
2. You sign in to your Anthropic account (or create one).
3. You authorize Claude Code to use your account.
4. The CLI receives a token and stores it locally.

After this, Claude Code is ready to use. The token persists across sessions.

> **Tip**: If you are on a headless server (SSH, no browser), copy the URL printed in the terminal and open it on another device. After authorizing, the CLI will detect the token automatically.

### Method 2: API Key

If you use the Anthropic API directly (e.g., through a paid API plan), you can authenticate with your API key:

```bash
# Set as environment variable
export ANTHROPIC_API_KEY="sk-ant-api03-..."

# Then run Claude Code
claude
```

To make this permanent, add the export to your shell profile:

```bash
# bash
echo 'export ANTHROPIC_API_KEY="sk-ant-api03-..."' >> ~/.bashrc

# zsh
echo 'export ANTHROPIC_API_KEY="sk-ant-api03-..."' >> ~/.zshrc

# PowerShell (Windows)
[System.Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", "sk-ant-api03-...", "User")
```

> **Warning**: Never commit your API key to version control. Add `.env` files and credential files to your `.gitignore`.

## Anthropic Subscription Plans

Claude Code is available through Anthropic's subscription tiers:

| Plan | Price | Claude Code Access |
|---|---|---|
| **Free** | $0/mo | No Claude Code access |
| **Pro** | $20/mo | Includes Claude Code with usage limits |
| **Max** | $100/mo | Claude Code included with significantly higher usage limits |
| **API** | Pay-per-use | Full access, billed per token |

- **Pro ($20/mo)**: Gives you access to Claude Code with reasonable daily usage limits. Good for individual developers with moderate usage.
- **Max ($100/mo)**: Designed for heavy Claude Code users. Includes substantially higher rate limits so you can use Claude Code as your primary coding workflow throughout the day.
- **API**: Pay-per-token pricing with no subscription. You get full control and no hard usage caps (just billing). Best for teams, CI/CD pipelines, or very heavy usage.

To manage your subscription, visit [https://console.anthropic.com](https://console.anthropic.com).

## Settings Files Location

Claude Code stores its configuration and data in your home directory:

```
~/.claude/
  settings.json          # Global settings and preferences
  credentials.json       # Authentication tokens (do not share)
  projects/              # Per-project conversation history
```

On Windows (native), this is typically:

```
C:\Users\YourName\.claude\
```

> **Warning**: The `credentials.json` file contains your authentication tokens. Never share it or commit it to version control.

### Global Settings

You can view and modify settings through the CLI:

```bash
# Open settings
claude config
```

Or edit `~/.claude/settings.json` directly. Common settings include permission preferences and default behaviors.

## CLAUDE.md -- Project-Specific Instructions

The `CLAUDE.md` file is one of Claude Code's most powerful features. Place it in your project root to give Claude persistent context about your project.

### What to Include

Create a `CLAUDE.md` file in your project root:

```markdown
# Project: My Web App

## Tech Stack
- Frontend: React 18 with TypeScript
- Backend: Node.js with Express
- Database: PostgreSQL with Prisma ORM
- Testing: Jest + React Testing Library

## Architecture
- /src/components/ -- React components
- /src/api/ -- Express route handlers
- /src/db/ -- Prisma schema and migrations
- /src/utils/ -- Shared utility functions

## Coding Standards
- Use functional components with hooks (no class components)
- All new code must have tests
- Use named exports, not default exports
- Error handling: always use custom AppError class from src/utils/errors.ts

## Common Commands
- `npm run dev` -- Start development server
- `npm test` -- Run all tests
- `npm run lint` -- Lint with ESLint
- `npm run db:migrate` -- Run Prisma migrations

## Important Notes
- Never modify files in /src/generated/ -- these are auto-generated by Prisma
- The .env file must have DATABASE_URL set for database commands to work
- Use `pnpm` not `npm` for package management
```

### CLAUDE.md Hierarchy

Claude Code reads `CLAUDE.md` files at multiple levels:

1. **Project root** (`/project/CLAUDE.md`) -- Main project context.
2. **Subdirectories** (`/project/src/components/CLAUDE.md`) -- Context specific to that part of the codebase.
3. **Home directory** (`~/.claude/CLAUDE.md`) -- Global instructions that apply to all projects.

More specific files take precedence over general ones when there are conflicts.

## Model Selection

Claude Code can use different Claude models. You can change the model during a session:

```
/model

# Or specify directly
/model claude-sonnet-4-20250514
```

Available models typically include:

- **claude-sonnet-4-20250514** -- Fast, efficient, great for most coding tasks (default)
- **claude-opus-4-20250514** -- Most capable, best for complex reasoning and large refactors

> **Tip**: Sonnet is the default and handles the vast majority of coding tasks well. Switch to Opus for particularly complex architectural decisions or multi-system refactors.

You can also set a default model via environment variable:

```bash
export CLAUDE_MODEL="claude-opus-4-20250514"
```

## MCP Server Configuration

The Model Context Protocol (MCP) lets you extend Claude Code with external tools and data sources. MCP servers can provide access to databases, APIs, documentation, file systems, and more.

### Configuration Location

MCP servers are configured in your settings. You can configure them at the project level or globally:

**Project-level** (`.claude/mcp.json` in your project root):

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "postgresql://user:pass@localhost:5432/mydb"
      }
    }
  }
}
```

**Global** (`~/.claude/mcp.json`):

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/allowed/dir"]
    }
  }
}
```

### Common MCP Servers

| Server | Purpose | Package |
|---|---|---|
| Filesystem | Read/write files in specified directories | `@modelcontextprotocol/server-filesystem` |
| PostgreSQL | Query PostgreSQL databases | `@modelcontextprotocol/server-postgres` |
| GitHub | Interact with GitHub repos, issues, PRs | `@modelcontextprotocol/server-github` |
| Memory | Persistent key-value memory across sessions | `@modelcontextprotocol/server-memory` |
| Brave Search | Web search capabilities | `@modelcontextprotocol/server-brave-search` |

For a full list of available MCP servers, see [https://github.com/modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers).

### Adding an MCP Server via CLI

```bash
claude mcp add my-server-name npx -y @modelcontextprotocol/server-whatever
```

### Verifying MCP Servers

Once configured, Claude Code will load MCP servers on startup. You can verify they are connected:

```
/mcp
```

This shows the status of all configured MCP servers and their available tools.
